* Installation
:PROPERTIES:
:CUSTOM_ID: installation
:END:

** 1. Hugo サイトの作成

#+begin_src bash
hugo new site mysite
cd mysite
git init
#+end_src

** 2. Blowfish テーマを submodule として追加

#+begin_src bash
git submodule add -b main https://github.com/nunocoracao/blowfish.git themes/blowfish
#+end_src

** 3. テーマ設定ファイルのコピー

#+begin_src bash
cp themes/blowfish/config/_default/* config/_default/
#+end_src

このコピーは初回セットアップ時のみです。テーマ更新時の設定反映は
[[#submodule-管理][Submodule 管理]] を参照してください。

** 4. Emacs パッケージのインストール

~straight.el~ を利用（~orgx/orgx-export.el~ で設定済み）

#+begin_src emacs-lisp
M-x straight-pull-all
#+end_src

ox-hugo がロードされていることを確認

#+begin_src emacs-lisp
M-: (featurep 'ox-hugo)  ; => t
#+end_src

* Submodule 管理
:PROPERTIES:
:CUSTOM_ID: submodule-管理
:END:

Blowfish テーマは Git submodule として管理されています（~.gitmodules~ で
~branch = main~ を追跡。Hugo Modules（~go.mod~）は使用していません）。
リポジトリを clone した直後や、テーマ更新時は以下を実行します。

** 初回 clone 時（submodule を含める）

#+begin_src bash
git clone --recursive https://github.com/<your-repo>.git
cd <your-repo>
#+end_src

すでに clone 済みの場合：

#+begin_src bash
git submodule update --init --recursive
#+end_src

** Blowfish テーマを最新に更新する手順

Blowfish は Semantic Versioning のタグを切らず ~main~ ブランチを直接追跡する
運用のため、更新時は「取得して終わり」ではなく以下の順番で確認します。

*** 1. 現在のバージョンを記録（切り戻し用）

#+begin_src bash
git -C themes/blowfish rev-parse HEAD > /tmp/blowfish-before.rev
#+end_src

*** 2. submodule を最新に更新

#+begin_src bash
git submodule update --remote --merge themes/blowfish
#+end_src

*** 3. 設定ファイルの差分を確認

テーマ側 ~config/_default/~ に新しいキーが増えていないか必ず diff します。
差分があれば自サイトの ~config/_default/~ に手動でマージしてください
（上書きコピーはしないこと。ローカルのカスタマイズが失われます）。

#+begin_src bash
diff -ru config/_default/ themes/blowfish/config/_default/
#+end_src

*** 4. Hugo バージョン要件を確認

~themes/blowfish/config/_default/module.toml~ の ~min~ が上がっていないか
確認し、上がっていればローカルの Hugo と CI 側を両方追随させます。

#+begin_src bash
cat themes/blowfish/config/_default/module.toml
hugo version
#+end_src

CI（~.github/workflows/deploy.yml~）の ~hugo-version:~ もこの値に合わせて
更新すること（[[#deploy][Deploy]] 参照）。ここがズレると、ローカルでは
ビルドできるのに CI だけ失敗する事態になります。

*** 5. ローカルビルドで検証してからコミット

#+begin_src bash
hugo server --buildDrafts --disableFastRender
#+end_src

- ~failed to extract shortcode~ 等のエラーが出ないこと
- WARN の deprecated 設定キーが増えていないこと（出ていれば
  [[#configuration][Configuration]] のファイルを合わせて修正）

問題なければコミットします：

#+begin_src bash
git add themes/blowfish config/_default
git commit -m "chore: update blowfish theme"
#+end_src

問題があれば、記録しておいた commit に戻します：

#+begin_src bash
cd themes/blowfish && git checkout $(cat /tmp/blowfish-before.rev) && cd ../..
git add themes/blowfish
git commit -m "revert: rollback blowfish theme update"
#+end_src

** すべての submodule を更新

#+begin_src bash
git submodule update --remote --recursive
#+end_src

** Submodule 状態確認

#+begin_src bash
git submodule status
#+end_src

** Submodule を強制的に同期

リモートURL変更などがあった場合：

#+begin_src bash
git submodule sync --recursive
git submodule update --init --recursive
#+end_src

** よくあるトラブル対処

submodule が壊れた場合：

#+begin_src bash
git submodule deinit -f themes/blowfish
rm -rf .git/modules/themes/blowfish
git submodule update --init --recursive
#+end_src

* Blowfish テーマについて
:PROPERTIES:
:CUSTOM_ID: blowfish-テーマについて
:END:

[[https://blowfish.page/][Blowfish]] は [[https://nunocoracao.github.io/][Nuno Coração]] が開発する
Hugo 向けの高機能テーマ。本サイトでは ~themes/blowfish~ に Git submodule として
組み込んでいます（導入・更新手順は [[#submodule-管理][Submodule 管理]] を参照）。

** リンク

| 用途           | URL                                                           |
|----------------+----------------------------------------------------------------|
| 公式サイト     | [[https://blowfish.page/]]                                    |
| ドキュメント   | [[https://blowfish.page/docs/]]                                |
| GitHub リポジトリ | [[https://github.com/nunocoracao/blowfish]]                 |
| Changelog      | [[https://github.com/nunocoracao/blowfish/releases]]           |

** バージョン運用上の注意

Blowfish は明示的な SemVer タグを切らず、~main~ ブランチへの直接コミットを
リリースとして扱う運用です。そのため本リポジトリの ~.gitmodules~ でも
タグではなく ~branch = main~ を追跡しています。

- 「最新版」を取り込む＝~main~ の最新コミットを取り込むことを意味し、
  タグ固定によるロールバック起点が無い点に注意（切り戻し手順は
  [[#submodule-管理][Submodule 管理]] の更新手順内に記載）
- 最低 Hugo バージョンは ~themes/blowfish/config/_default/module.toml~ の
  ~min~ で管理される。更新の都度、ローカルとCI（[[#deploy][Deploy]] の
  ~hugo-version~）の両方を追随させる必要がある

** 本サイトで使用している主な機能

| 機能                      | 設定/実体                                        |
|---------------------------+---------------------------------------------------|
| カラースキーム・レイアウト | ~config/_default/params.toml~                     |
| 記事カバー画像            | 各記事ディレクトリの ~cover.*~（~deploy.zsh~ が自動配置） |
| ~carousel~ 等の shortcode | ~themes/blowfish/layouts/shortcodes/~ 内蔵ショートコード |
| 多言語設定の土台          | ~config/_default/languages.en.toml~（英語のみ運用） |

新しい Blowfish の機能（追加ショートコード・新規 params 項目など）を使う場合は、
テーマ更新後に ~themes/blowfish/exampleSite/~ 配下のサンプル設定を参照すると
該当する ~params.toml~ のキーを確認しやすい。

* Deploy
:PROPERTIES:
:CUSTOM_ID: deploy
:END:

** GitHub Actions

#+begin_src yaml
# .github/workflows/deploy.yml
- uses: actions/checkout@v4
  with:
    submodules: true
    fetch-depth: 0

- name: Setup Hugo
  uses: peaceiris/actions-hugo@v3
  with:
    hugo-version: '0.157.0'
    extended: true

- name: Build
  run: hugo --minify
#+end_src

~hugo-version~ はテーマ更新時に上がった ~module.toml~ の ~min~ 要件に
必ず追随させること（[[#submodule-管理][Submodule 管理]] 参照）。放置すると
ローカルビルドは通るのに CI だけ失敗する原因になります。

** 手動ビルド

#+begin_src bash
hugo --minify
# 出力先: ./public/
#+end_src

** deploy.zsh（ローカルからの手動デプロイ）

GitHub Actions とは別に、ローカル環境から直接デプロイするための zsh スクリプト
~deploy.zsh~ を用意しています。カバー画像の自動配置・ビルド・公開用ディレクトリへの
同期・コミット & push までを一括で行います。

*** 使い方

#+begin_src bash
# ICLOUD_USE 未指定時のデフォルト（${HOME}/Projects）で実行
./deploy.zsh

# サイトルート（mysite/, deploy/ の親ディレクトリ）を明示的に指定する例
ICLOUD_USE=~/Documents/Projects ./deploy.zsh

# カレントディレクトリをサイトルートとして使う場合
ICLOUD_USE="$(pwd)" ./deploy.zsh
#+end_src

*** オプション

| オプション       | 説明                                                        |
|------------------+---------------------------------------------------------------|
| ~--dry-run~      | Hugo ビルドまで実行し、~rsync~ 同期と ~git push~ の両方をスキップする |
| ~--skip-cover~   | カバー画像の自動配置をスキップする                           |
| ~--help~ / ~-h~  | 使い方を表示                                                 |

*** 処理の流れ

1. *Pre-flight checks* — ~hugo~ / ~git~ / ~rsync~ の存在と、
   ~HUGO_DIR~・~PUBLIC_DIR~（いずれも ~ICLOUD_USE~ 配下）の存在を確認
2. *Placing cover images* — カバー未設定の記事に、front matter の
   ~date~／~publishDate~ から読み取った公開月ベースでカバー画像を配置
   （冪等: 既存の ~cover.*~ があるものは上書きしない。同一カバーグループの
   ファイルパスはキャッシュし、記事ごとに再チェックしない）
3. *Building site with Hugo* — ~public/~ を作り直して ~hugo --minify~
   （~--dry-run~ 指定時はここで終了し、以降の同期・pushは実行されない）
4. *Syncing to deploy directory* — ~rsync -a --delete --checksum~ で
   ビルド成果物を ~PUBLIC_DIR~ に同期
5. *Committing and pushing* — ~PUBLIC_DIR~ 側で差分があれば
   ~git add --all~ → commit → push

途中でエラーが出た場合、実行は各ステップの ~abort~ で即座に中断されます
（~set -euo pipefail~）。~carousel~ shortcode 未検出のようなビルドエラーは
[[#submodule-管理][Submodule 管理]] の「Blowfish テーマを最新に更新する手順」で
案内している設定差分確認が漏れているケースが多いので、あわせて確認してください。
